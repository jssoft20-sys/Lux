# PayGo

Платёжная касса для Telegram: пополнение и вывод средств игроков через кассы букмекеров (**1xbet** и **1win** включены), бот поддержки с автоматизацией, мобильная админ-панель `https://wwweeewww.fit/paygo/`.

```
/home/PayGo/                 ← весь проект в одном каталоге
├── backend/paygo/          FastAPI-бэкенд: API, сервисы, провайдеры касс, воркеры, тексты бота
├── bot/paygobot/           Telegram-боты: клиентский (@PayGoXBot) и оператор (@PayOperator_bot)
├── frontend/admin/         Админ-панель (статический SPA без сборки)
├── migrations/             Alembic-миграции
├── deployment/             systemd-юниты, nginx
├── scripts/                install, migrate, create_admin, backup, restore, update, healthcheck
├── docs/                   Архитектура, безопасность, поддержка, API, эксплуатация
├── tests/                  pytest (SQLite и PostgreSQL)
├── venv/ data/ logs/ backups/   создаются установщиком
└── .env                    все секреты и токены (права 600)
```

Процессы: **backend** (HTTP :7035), **worker** (фоновые задачи), **bot** (клиентский бот), **support** (бот-оператор). Все используют одну базу PostgreSQL и один `.env`.

---

## 1. Требования

* Ubuntu 22.04/24.04 (или Debian 12), root-доступ
* Python 3.10+ (установщик выбирает самый новый из 3.10–3.12)
* PostgreSQL 14+ (ставится установщиком)
* nginx с HTTPS на домене `wwweeewww.fit` (уже есть — подключается одной строкой)
* Токены ботов уже в `.env` из архива; доступ к API касс (1xbet: Servcul — логин, пароль кассира, cashdeskId, hash; 1win: API-ключ)
* MacroDroid на телефоне с приложением банка — для подтверждений платежей

## 2. Установка

Архив `paygo.zip` содержит папку `PayGo/`. Загрузите его в `/home/` и выполните от root:

```bash
apt install -y unzip sudo
unzip -o /home/paygo.zip -d /home/
cd /home/PayGo && bash scripts/install.sh
```

Скрипт ставит пакеты (Python, PostgreSQL, nginx), создаёт пользователя `paygo` с домашним каталогом `/home/PayGo`, виртуальное окружение, пользователя и базу PostgreSQL `paygo` (пароль записывает в `.env`), применяет миграции и seed (кассы 1xbet и 1win, кнопки банков), ставит systemd-юниты `paygo-*` и nginx-сниппеты. Готовый `.env` из архива не трогает; повторный запуск безопасен.

## 3. .env

Уже заполнен: секреты, токены ботов, `PORT=7035`, `BASE_PATH=/paygo`, `PUBLIC_URL=https://wwweeewww.fit`. Проверить/дополнить:

```bash
nano /home/PayGo/.env
```

* `SMTP_USER`, `SMTP_PASSWORD` — почта Timeweb для подтверждения e-mail (необязательно).
* `ADMIN_TELEGRAM_CHAT_IDS` — Telegram ID операторов для критических уведомлений через бота-оператора.
* `ADMIN_IP_ALLOWLIST` — при желании ограничить вход в панель адресами офиса/VPN.

Все секреты — только в `.env` (права 600), в Git и в коде их нет. Комментарии в `.env` — только отдельными строками (systemd передаёт строку целиком).

## 4. База данных

Создаётся установщиком: пользователь `paygo`, база `paygo`, `DATABASE_URL=postgresql+psycopg://paygo:<пароль>@127.0.0.1:5432/paygo`. Вручную:

```bash
sudo -u postgres psql -c "CREATE USER paygo WITH PASSWORD 'СИЛЬНЫЙ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE paygo OWNER paygo;"
```

## 5. Миграции

```bash
cd /home/PayGo && scripts/migrate.sh            # = alembic upgrade head
venv/bin/python -m paygo.cli seed               # кассы и кнопки банков — идемпотентно
```

## 6. Администратор

```bash
sudo -u paygo /home/PayGo/scripts/create_admin.sh --username admin --role owner
```

Команду запускайте одну — пароль спрашивается интерактивно (≥10 символов, буквы разного регистра и цифра). Роли: `viewer`, `operator` (заявки, поддержка, клиенты), `admin` (+ кассы, настройки, логи), `owner` (+ администраторы, безопасность).

## 7–9. Запуск backend, ботов и worker

```bash
systemctl restart paygo-backend paygo-worker paygo-bot paygo-support
systemctl is-active paygo-backend paygo-worker paygo-bot paygo-support
curl -s http://127.0.0.1:7035/healthz          # {"ok":true,...}
```

Боты работают по long polling (webhook Telegram не нужен). Вручную для отладки: `set -a; . ./.env; set +a; venv/bin/python -m paygo.server`.

## 10. Домен

Сниппеты уже в `/etc/nginx/snippets/paygo*.conf`, зоны limit_req — в `/etc/nginx/conf.d/paygo-zones.conf`. В файл домена (`/etc/nginx/sites-enabled/wwweeewww.fit`) внутрь блока `server { listen 443 ssl; ... }` добавьте одну строку:

```nginx
include /etc/nginx/snippets/paygo.conf;
```

```bash
nginx -t && systemctl reload nginx
curl -s -o /dev/null -w "%{http_code}\n" https://wwweeewww.fit/paygo/     # 200
```

Проксируется только префикс `/paygo/`; другие проекты, порты и `location` того же домена не затрагиваются. Если конфигурации домена нет — `deployment/nginx/paygo-site-http.example.conf` + `certbot --nginx -d wwweeewww.fit`.

## 11. HTTPS

Сертификат домена уже используется. Приложение за прокси доверяет `X-Forwarded-Proto` (`TRUST_PROXY=true`), cookie ставятся `Secure; HttpOnly; SameSite=Strict`, HSTS включён. Заходить в панель только по HTTPS-домену.

## 12. systemd

Юниты `paygo-backend`, `paygo-worker`, `paygo-bot`, `paygo-support` (пользователь `paygo`, `Restart=always`, логи `/home/PayGo/logs/*.log`).

```bash
systemctl status paygo-backend paygo-worker paygo-bot paygo-support --no-pager
journalctl -u paygo-backend -n 100
tail -f /home/PayGo/logs/backend.log /home/PayGo/logs/bot.log
```

Docker-вариант: `docker compose up -d` (PostgreSQL + все процессы, порт 7035 на 127.0.0.1).

## 13. Health check

```bash
/home/PayGo/scripts/healthcheck.sh                   # backend, БД, все юниты
curl -s http://127.0.0.1:7035/healthz
curl -s https://wwweeewww.fit/paygo/api/health       # версия, БД, наличие токенов
```

## 14. Backup

```bash
/home/PayGo/scripts/backup.sh                        # /home/PayGo/backups/paygo-YYYYmmdd-HHMM.tar.gz (pg_dump + data/ + .env), 14 копий
(crontab -u paygo -l 2>/dev/null; echo "0 3 * * * /home/PayGo/scripts/backup.sh") | crontab -u paygo -
```

## 15. Rollback

```bash
systemctl stop paygo-bot paygo-support paygo-worker paygo-backend
/home/PayGo/scripts/restore.sh /home/PayGo/backups/paygo-YYYYmmdd-HHMM.tar.gz
systemctl start paygo-backend paygo-worker paygo-bot paygo-support
```

## 16. Обновление

```bash
unzip -o /home/paygo.zip -d /tmp/paygo-new
/home/PayGo/scripts/update.sh /tmp/paygo-new/PayGo    # backup → стоп ботов → rsync → pip → миграции → рестарт → healthcheck
```

`.env`, `data/`, `venv/`, `logs/`, `backups/` при обновлении не затрагиваются. Во время обновления лишние экземпляры PayGo (ручные запуски, старый docker compose) останавливаются автоматически.

После копирования файлов скрипт передаёт управление уже новой своей копии (`update.sh --stage2`), поэтому новые шаги обновления (миграции, seed, тестовая заявка) выполняются в том же запуске, а не со следующего раза.

## 17. Лишние экземпляры (409 Conflict, бот отвечает через раз)

```bash
/home/PayGo/scripts/kill_stray.sh              # стоп юнитов → убить всё лишнее только у PayGo → старт юнитов → healthcheck
/home/PayGo/scripts/kill_stray.sh --dry-run    # только показать, что было бы остановлено
/home/PayGo/scripts/kill_stray.sh --sessions   # + завершить все сеансы админки (все входят заново через подтверждение в боте)
```

Скрипт видит только процессы PayGo: python из `/home/PayGo/venv`, модули `paygobot.*` / `paygo.*`, docker-контейнеры `paygo-*`. Другие проекты, сайты и боты на том же сервере не затрагиваются.

## После установки: настройка в панели

1. **Кассы** → 1xbet → Изменить: учётные данные Servcul, «Проверить» (статус «Онлайн», баланс). 1win → API-ключ. Здесь же: эмодзи кнопки, **фото и тексты шагов** (скриншот «где взять ID» для пополнения, «ID для вывода», «код вывода»), город/адрес вывода для кассы, лимиты и пороги автоотключения.
2. **Кошельки** → «Добавить»: фото QR вашего банка, строка ELQR или ссылка банка. Режим выбора (**Случайный** — реквизиты чередуются, **Один основной** — по приоритету) — в Расширенных настройках → Пополнения; кнопки банков под QR включаются галочками в Настройки → Попол.
3. **MacroDroid** → скопировать адрес webhook (ключ показывается по кнопке), настроить макрос: триггер «Уведомление получено» от приложения банка → действие «HTTP-запрос» POST, Content-Type `application/json`, тело `{"text":"{not_text}","title":"{not_title}","app":"{not_app}"}`. Кнопка «Тест» проверяет связку. Белый список IP и режим «только с подписью» — там же.
4. **Настройки → Тексты**: все сообщения бота (приветствие, шаги, подпись под QR, «Пополнение отменено», «Пополнено», тексты вывода). Подстановки: `{name} {support} {cash} {emoji} {player} {amount} {cur} {min} {max} {minutes} {reason} {sla} {city} {address}`. Premium-эмодзи: `[emoji:ID:😎]` при включённом переключателе.
5. **Настройки → Выводы**: город `Бишкек`, адрес `ул. PayGo Online`, сроки, общая инструкция с фото. **Пополнения**: время на оплату, уникальные тыйыны, кнопки сумм, просьба прислать чек, надписи карточки QR.
6. **Безопасность**: сменить пароль, проверить сессии; **Push** — включить уведомления на телефоне.
7. **Premium-эмодзи.** Тексты по умолчанию уже содержат premium-эмодзи из вашего образца (👋 ⚡️ 💰 👩‍💻 🔝 💬 👍 📌 💵 ⏰ ❌ ℹ️, логотипы 1xbet 😎 и 1win 🥇, банков MBank/О!Деньги/MegaPay 🤩), переключатель «Premium-эмодзи» включён. Telegram показывает их только у ботов с **коллекционным username с fragment.com**: купите username на Fragment, назначьте его боту в BotFather (Bot Settings → Usernames) и нажмите Настройки → Бот → «Проверить premium-эмодзи». Пока Telegram отказывает, бот автоматически показывает обычные эмодзи, ничего не ломается. ID своих эмодзи: перешлите сообщение с нужным эмодзи боту @JsonDumpBot и возьмите `custom_emoji_id`; формат в текстах — `[emoji:ID:😎]`, у касс и кнопок банков — поле «ID premium-эмодзи».

Панель на телефоне: заявка открывается отдельной страницей (`#/deposit/12`, `#/withdrawal/7`; старые ссылки `#/deposits/12` из уведомлений ведут туда же). Шапка страницы: назад, имя клиента (нажатие — профиль), кнопка чата и меню ⋮ («Отложить заявку» / «Вернуть в работу», «Поиск по ID», «Изменить», «Взять в работу», «Через Optima24», «Оплатить в Optima24», «Отменить заявку», «Заблокировать»). Карточка пополнения: пометка о найденном платеже, кнопка «Чат», ID с копированием, дата, статус, чек клиента, сумма с карандашом (поле с ✓ / ✕ прямо в карточке); ниже — «Транзакции / Ордера»: платежи из банка на эту сумму (MacroDroid, почта, выписка) и другие заявки на неё. Карточка вывода: логотип банка клиента, ID, дата, статус, сумма, «Ген QR / Ориг QR», под QR — «Загрузить чек» и «Оплатить в Optima24» (открывает Optima24 на экране подтверждения с получателем и суммой; появляется, когда у заявки есть строка ELQR — из фото QR или из ссылки банка, которую сервер разрешает сам). Дальше — букмекер, идентификатор, код верификации (у выводов), дата создания, свёрнутая история и другие заявки клиента по датам; внизу закреплены «Принять» и «Отказать». На Главной вывод можно потянуть вправо — «Отложить» (в отложенных — «Вернуть»). Быстрые ответы переставляются: зажать строку и потянуть. Модальные окна снизу (фильтр истории, подтверждения, редактирование, быстрые ответы, «Транзакции» в чате) тянутся пальцем: вверх — на весь экран, вниз — закрыть.

Чат с клиентом: «Написать клиенту» в заявке или профиле открывает диалог в разделе Чат. Сообщения уходят через бот поддержки, а если клиент его не открывал — через основной бот (ответы клиента попадают в тот же чат). Зажмите сообщение: «Ответить», для своих — «Изменить» и «Удалить» (меняется и у клиента в Telegram). Голосовые, видео, фото и файлы клиента открываются прямо в чате.

Рассылка: выбор бота, текст, картинка и тестовая отправка себе (Telegram ID); уходит всем клиентам бота. Отправка идёт в фоне (worker), под формой — история: дата, сколько отправлено, ошибки с причинами (аудитории и кнопки-ссылки доступны через API `POST /broadcast`).

Premium-эмодзи: основной бот показывает только premium-эмодзи. Обычные эмодзи в текстах и кнопках заменяются по таблице «Настройки → Бот → Premium-эмодзи: соответствия» (эмодзи и ID в строке), а те, для которых ID нет, убираются (переключатель «Только premium»). Исключение — клавиатура меню (📥 Пополнить / 📤 Вывести / ✉️ Помощь): она не может нести premium-эмодзи, поэтому там остаются обычные (тексты кнопок меняются в Настройки → Тексты).

Чат: у каждого клиента один диалог. Закрытое обращение при новом сообщении, «Чат с оператором» или файле в основном боте открывается заново — история остаётся в том же чате, вкладки «Открытые»/«Закрытые» показывают одну строку на клиента (старые дубли объединяются миграцией). Поиск над списком ищет и по чатам (имя, @username, Telegram ID), и по тексту сообщений — результаты в двух блоках «Чаты» и «Сообщения» (`GET /support/search?q=`). Три точки в чате — «Транзакции» (заявки клиента: суммы, статусы, кнопка «Чек», нажатие — страница заявки), «Профиль», «Взять в работу», «Вернуть боту», «Завершить».

Аватарки клиентов: фото профиля Telegram берётся через бот (основной или поддержки — тот, которого клиент запускал) раз в сутки при любом сообщении клиента, в фоне, не задерживая ответ бота. Картинка сжимается до 128 px JPEG и хранится в `uploads/avatars/<telegram_id>.jpg` (отдаётся только вошедшим сотрудникам), показывается в чатах, профиле клиента и заявках; без фото или при закрытом профиле — инициал имени. Убрал клиент фото — через сутки пропадёт и в панели.

Вход в панель: после логина и пароля основной бот присылает владельцу (Telegram ID из `LOGIN_APPROVER_TELEGRAM_ID`, по умолчанию 8274883903; можно переопределить в Расширенных настройках → Вход) сообщение с устройством, IP и временем и кнопками «✅ Подтвердить» / «❌ Отклонить». Экран панели в это время показывает проверку сессии; после подтверждения сессия живёт 30 дней (`LOGIN_SESSION_DAYS`). Запрос действует 3 минуты. Владелец должен один раз написать боту /start, иначе Telegram не даст боту отправить ему сообщение.

Поддержка на Claude: при заданном `ANTHROPIC_API_KEY` в `.env` (модель `ASSISTANT_MODEL`, по умолчанию `claude-opus-5`) первым клиенту отвечает Claude: смотрит реальные заявки клиента, сам зачисляет платёж, который пришёл по истёкшей или ошибочной заявке, повторяет зачисление после ошибки кассы и передаёт оператору жалобы, задержки выводов и всё, что требует человека (с кратким описанием в теме чата). Без ключа или при недоступности API работают прежние правила — бот не молчит. Выключатель: Расширенные настройки → Поддержка. Раздел «Первая линия» убран.

Настройки: четыре вкладки как в эталонной панели — «Основные» (пауза, заявки без чеков, оператор, подписка на канал, название канала, активные реквизиты), «Сайты» (каждая касса: включена / пополнения / выводы), «Выводы» (включить выводы, галочки банков, на которые касса переводит — выключенный банк бот не принимает и просит QR другого банка, порог обязательного чека) и «Попол.» (включить пополнения, уникальные тыйыны, банки под QR); переключатели и галочки сохраняются сразу, поля — кнопкой «Сохранить настройки». Тексты, эмодзи, поддержка, вход, уведомления, адрес выводов, время на оплату, курс доллара для аналитики — в «Расширенных настройках»; там же ссылки на Кассы, MacroDroid, Push и Сервер. Кошельки (QR/реквизиты, на которые платят клиенты) — раздел меню «Кошельки». Тема панели (Светлая / Тёмная, тёмная — серая как в Telegram) переключается в «Меню» и запоминается на устройстве.

Роли: оператор видит только работу с клиентами — Главная, История, Чат, Поиск, профиль клиента, «Аналитика» (балансы касс) и «Быстрые ответы»; Кошельки, Настройки, Логи, Рассылки, Выписки, Кассы и Безопасность есть только у администратора и владельца (те же ограничения стоят на API).

Бот больше ничего не удаляет: сообщения клиента, шаги и старые экраны остаются в чате (у старых экранов пропадают кнопки). Когда заявка на пополнение оплачена, отменена или истекла, её карточка с QR превращается в карточку статуса «ОПЛАЧЕНО / ОТМЕНЕНО / ВРЕМЯ ИСТЕКЛО» без QR и без кнопок банков — реквизиты закрытой заявки в чате не остаются.

1win: для проверки баланса портал 1win.win принимает вход только с идентификацией браузера, которую отправляла старая панель. В кассе 1win → Изменить → «Дополнительно (вход на 1win.win)» вставьте Fingerprint ID, Client ID и User-Agent из старого `config.json` (ключи `agent_fingerprint_id`, `agent_client_id`, `agent_user_agent`) или импортируйте всё разом: `venv/bin/python -m paygo.cli import-legacy /путь/к/старому/config.json --enable 1xbet,1win`.

Приложение для Android: `PayGo.apk` (пакет `kg.paygo.admin`) открывает панель 1 в 1 — чат, камера для чеков, cookies сохраняются, сессия та же, что в браузере. Установка: разрешить «Неизвестные источники», открыть apk. Исходники — `android/` (сборка описана в `android/README.md`).

Боты под нагрузкой: сообщение поддержки обрабатывается сразу (серия коротких сообщений, уже стоящих в очереди, объединяется без ожидания), один чат никогда не блокирует другие, нажатия во время обработки не теряются (ставятся в очередь, последние два — в приоритете), уведомления клиентам уходят параллельно и раньше рассылки, распознавание QR идёт в отдельном процессе (`QR_DECODE_WORKERS`, 0 — в том же процессе), а сторожевой поток перезапускает бот, если опрос Telegram перестал двигаться (systemd поднимает процесс за 3 секунды).

Автовыплаты (Optima24): PayGo может сам отправлять клиенту готовый вывод — тот же перевод на карту/QR, что оператор делает вручную в Optima24. Канал задаётся в `.env` (`PAYOUT_PROVIDER=optima24`, учётные данные `OPTIMA24_*` — только там, никогда в БД или архиве), включение и лимиты — в админке (Автовыплаты): `autopay_enabled` (общий выключатель), `autopay_dry_run` (тест: движок пишет в лог, что отправил бы, но денег не двигает), `autopay_max_amount` (потолок на одну выплату — выше оператор платит руками), `autopay_daily_cap` (лимит за день), `autopay_min_reserve` (не опускать баланс ниже), `autopay_low_balance` (порог предупреждения), `autopay_min_interval_seconds` (пауза между переводами, по умолчанию 18 с — банк просил 15–20, чтобы не заваливать запросами: движок шлёт не больше одного перевода за интервал, очередь расходится сама). Деньги на Optima24 пополняются с Optima Business вручную; пока баланс есть — выплаты идут, ниже порога владелец получает критическое уведомление «Пополните Optima24», ниже резерва — выплаты встают. Каждая автовыплата идёт под уникальным ключом (номер заявки): повтор невозможен, а перевод, оборвавшийся без ответа банка, помечается «проверьте вручную» и никогда не отправляется второй раз. В карточке вывода есть кнопка «Отправить через Optima24» (в тесте показывает, что было бы отправлено). **API самого Optima24 не публичный:** вход и перевод снимаются один раз из приложения (или берутся у техподдержки Optima) и вписываются в `backend/paygo/payouts/optima24.py` по метке `CAPTURE_REQUIRED`; до этого движок читает только баланс, а перевод честно отказывает, а не угадывает. **Код подтверждения перевода Optima присылает на e‑mail** — заведите отдельный ящик только для этих кодов, заполните `OPTIMA_OTP_IMAP_*` в `.env`, и PayGo сам читает код из почты и подтверждает перевод (телефон не нужен). Проверка ящика: `python -m paygo.cli optima-otp-test`. Выплаты идут по одной с паузой 15–20 с, поэтому код всегда относится к текущему переводу; не пришёл за отведённое время — заявка уходит оператору, перевод не повторяется. **Несколько аккаунтов Optima24** (несколько телефонов) задаются в `OPTIMA24_ACCOUNTS` (JSON-список логинов/паролей): движок сам выбирает аккаунт с достаточным балансом (самый полный), баланс в статусе — сумма по всем, пауза 15–20 с общая, почтовый ящик кодов один. Face ID роли не играет: это локальная разблокировка приложения, серверу нужен токен сессии (снимается один раз с авторизованного телефона), а не лицо. Автоматизация приватного API мобильного банка может нарушать условия банка — согласуйте с Optima.

Выводы: в заявке две вкладки QR — «С суммой» (QR клиента, пересобранный с суммой вывода, под ним кнопки банков) и «Оригинал» (фото клиента). Если бот не смог прочитать QR, в заявке есть «Распознать QR» (усиленное распознавание: наклон, тень, блик, мелкий код) и «Ввести вручную». Для выводов от суммы `withdraw_receipt_min` (по умолчанию 10 000) перед «Перевёл» нужно прикрепить чек перевода (камера или галерея) — он уходит клиенту вместе с «Вывод выполнен».

Выписки (резерв к MacroDroid): раздел меню **«Выписки»** — загрузка банковской выписки (PDF, XML, CSV) на случай, когда уведомление MacroDroid не дошло. PayGo разбирает файл, берёт из него только входящие платежи и **зачисляет заявку по двум проверкам сразу**: (1) сумма строки совпадает с суммой ожидающей заявки до тыйына и (2) дата-время строки попадает в окно этой заявки (платёж не может относиться к заявке, которой ещё не было, или к той, чьё окно он пропустил). Зачисляется только когда обеим проверкам отвечает ровно одна заявка — иначе строка идёт «на проверку» оператору. Исходящие строки (выплаты кассы) пропускаются, а повторная загрузка того же файла ничего не задваивает (каждая строка учтена один раз по устойчивому ключу). Переключатель «Автозачисление» можно выключить — тогда PayGo только показывает совпадения, не трогая деньги. Отчёт после загрузки: строк в выписке, поступлений, зачислено, на проверку, повторов. Проверено на реальной выписке Optima (485 операций за 4 дня: 32 входящих, 453 исходящих — все разобраны с датой и знаком суммы).

Тема панели: «Меню» → «Тема» — Светлая или Тёмная (серая, как ночная тема Telegram: фон `#141414`, карточки `#212121`). Выбор хранится в браузере (`localStorage`, ключ `paygo_theme`) и применяется до первой отрисовки, без мигания. Сезонного оформления (снег, листья, гирлянда) больше нет.

Тестовый вывод для проверки панели создаётся сам при первом обновлении через `scripts/update.sh` (метка `data/.demo_withdrawal`, нужна хотя бы одна касса); вручную — `venv/bin/python scripts/demo_withdrawal.py --qr "https://qr.finik.kg/f36e0f6a-1f22-4f34-a177-71444f6c91aa?type=t" --amount 150`. Заявка демо-клиента «Тест PayGo» появится на Главной с логотипом Finik, «Ген QR / Ориг QR», кнопкой «Оплатить в Optima24» и «Принять / Отказать» (кассу не трогает, автовыплата её пропускает; примите или отклоните как обычную). Подходит любая ссылка банка или строка ELQR.

Пополнения: зачисляется ровно та сумма, что пришла из банка — с тыйынами. Если клиент оплатил без тыйынов (900.00 вместо 900.37) и такая заявка одна, она всё равно зачисляется — на 900.00. Разбор суммы из уведомления банка берёт именно сумму платежа, а не баланс после операции, комиссию, номер телефона отправителя, маску карты или дату. Кнопка «Зачислить на счёт игрока» в панели спрашивает фактически оплаченную сумму (по умолчанию подставлен платёж из банка, иначе сумма заявки): в кассу уходит ровно она, в карточке заявки видно «Платёж» и «Зачислено». Если касса в ответе вернула другую сумму, в Логах появляется предупреждение «Касса ответила другой суммой».

1win: у кассы три поля — API key (пополнения и выводы), логин и пароль от 1win.win (только для баланса).

Бот: `/start` показывает приветствие и клавиатуру Пополнить / Вывести / Помощь; «Помощь» отвечает только контактом оператора. Каждый шаг заменяет предыдущее сообщение бота (в чате остаётся приветствие и итог), фото клиента после обработки удаляются. Заявка на пополнение живёт `payment_timeout_seconds` (5 мин): после истечения QR удаляется, клиент получает «Пополнение отменено… Создайте новую заявку», при оплате — «✅ Пополнено». Поддержка решает проблемы из панели: изменить сумму к оплате (QR пересобирается), ID игрока, зачислить через API, отклонить, посмотреть чек клиента. В списке заявок видно платёж из банка: зелёная метка — зачислен, жёлтая — пришло уведомление на такую же сумму, но заявка ещё не закрыта. Лишние сообщения клиента (голосовые, видео, файлы) во время заявки бот убирает; вне заявки они попадают оператору в Чат.

## Расшифровка голосовых

Бот поддержки умеет переводить голосовые клиента в текст: расшифровка появляется под голосовым в чате панели, а бот отвечает на неё так же, как на обычное текстовое сообщение (те же правила, Claude и передача оператору). По умолчанию выключено.

* **На своём сервере (бесплатно, без внешних сервисов):** `venv/bin/pip install -r requirements-stt.txt`, затем в `.env`: `STT_PROVIDER=local`, `STT_MODEL=small` (варианты: `tiny` / `base` / `small` / `medium`; `small` ≈ 500 МБ, качество для русского и кыргызского нормальное, `medium` точнее, но заметно медленнее). Модель скачивается один раз при первом голосовом (нужен доступ в интернет с сервера); GPU не нужен — на CPU (`STT_DEVICE=cpu`, `STT_COMPUTE_TYPE=int8`) голосовое на 10–15 секунд расшифровывается за несколько секунд. Перезапустите бот поддержки после изменения `.env`.
* **Через OpenAI:** `STT_PROVIDER=openai` и `OPENAI_API_KEY=...` (Whisper API, файл уходит в OpenAI; ключ — только в `.env`).

Язык определяется автоматически (русский / кыргызский). Тишина и шум не превращаются в «Спасибо за просмотр» и подобный мусор — такие расшифровки отбрасываются, голосовое остаётся без текста. Голосовое сначала получает обычный ответ «файл получен», а через несколько секунд — ответ по расшифровке; пока идёт распознавание, клиент видит «печатает…».

Язык бота (русский / кыргызский): клиент переключает язык командой `/lang` (она есть в меню команд бота) или кнопкой «🌐 Язык / Тил» (callback `lang`, её можно добавить к любому сообщению из панели) — бот показывает «🇷🇺 Русский / 🇰🇬 Кыргызча», запоминает выбор в профиле клиента (`users.language`) и сразу показывает главное меню и клавиатуру на новом языке; при первом обращении язык берётся из настроек Telegram клиента. Переводы всех экранов встроены: служебные строки и кнопки — `bot/paygobot/texts.py`, тексты из «Настройки → Тексты» — `KG_TEXTS` в `backend/paygo/services/bot_texts.py` (те же подстановки и premium-эмодзи), уведомления о статусах заявок (пополнено, отменено, вывод в обработке / выполнен / отклонён) бот тоже отдаёт кыргызскому клиенту по кыргызскому шаблону. Кыргызский клиент никогда не видит смесь языков: даже если русский текст изменён в панели, ему показывается встроенный кыргызский вариант; свой кыргызский текст задаётся через API настроек (`POST /paygo/api/settings`, ключ `<ключ>__kg`, например `greeting_text__kg`) — он имеет приоритет, а сброс текста к умолчанию удаляет и его. Тексты шагов и инструкция, заданные у конкретной кассы, написаны по-русски и показываются только русскоязычным клиентам (город и адрес кассы подставляются в кыргызскую инструкцию). Кнопки клавиатуры распознаются на обоих языках, поэтому старая клавиатура на экране после переключения продолжает работать.

* **Аналитика:** «Баланс · оборот кассы» (сумма пополнений и выводов за период) в лимитах шлюзов и «Оборот кассы» в разбивке по шлюзам; выбор периода (сегодня / 7 дней / 30 дней / всё время / свои даты); «≈ $» по курсу `usd_rate` (Расширенные настройки → Бот → Аналитика).
* **Режим оператора:** операторам доступны только заявки, чаты, поиск, профиль клиента, аналитика и быстрые ответы.

## Что нового в 1.8

* **Импорт выписок (раздел «Выписки»).** Загрузка банковской выписки PDF / XML / CSV как резерв к MacroDroid: PayGo разбирает файл, берёт входящие платежи и зачисляет заявку по двум проверкам — точная сумма (с тыйынами) **и** попадание времени строки в окно заявки. Новый сервис `services/statements.py`, эндпоинт `POST /statements/import`, экран загрузки с отчётом. Разобрана реальная выписка Optima на 485 операций. Приходит в панель через `/live`, применяется на лету, уважает «уменьшить движение». Тосты-уведомления переоформлены (иконка в цветной плашке).

## Что нового в 1.1

* **Бот всегда «в тонусе».** На каждое сообщение и нажатие клиент сразу видит «печатает…» (и дальше, пока идёт проверка ID или кода в кассе, ответ Claude в поддержке). Проверка ID/кода показывается прямо на экране шага; ошибка на шаге с фото меняет подпись того же фото — новых сообщений не сыпется. Соединение с базой держится тёплым (keep-alive раз в 30 с, TCP keepalive, быстрые таймауты), настройки и кассы прогреваются при старте: первый клиент после тихого дня получает такой же мгновенный ответ, как и сотый.
* **Самолечение.** Серия сбоев `getUpdates` сначала пересоздаёт HTTP-клиент Telegram, потом перезапускает процесс (systemd поднимает за 3 с). Сторожевой поток перед перезапуском сохраняет offset обновлений — старая пачка нажатий не проигрывается дважды. После простоя старые тексты из очереди (старше 15 минут) не выполняются как новые команды; фото чеков и нажатия сохраняются. Проверка ID у кассы — короткий таймаут (12 с) и один повтор при сетевой ошибке; финансовые запросы, как и раньше, не повторяются никогда.
* **Админка: всё редактирование — в модальном окне.** Тап по заявке открывает карточку снизу со всеми действиями («Зачислить», «Перевёл», «Изменить», «Отменить», «Чек», «Написать», «Отказать»); «Изменить» — второе модальное окно поверх. Отдельной страницы заявки нет; ссылки `#/deposits/12` из уведомлений и чата открывают Главную с карточкой сверху. Открытая карточка сама обновляется, когда приходит платёж или меняется статус.
* **Обновление.** `scripts/update.sh` больше не трогает `logs/` и `backups/`, после копирования возвращает файлы пользователю `paygo` и подхватывает изменённые systemd-юниты.
