# Эксплуатация

## Ежедневно
* Админка (`/paygo/`) — экран телефона с нижней навигацией **Главная / История / Чат / Поиск / Меню**.
* Главная → «Актуальные» (пополнения в ожидании / с ошибкой и активные выводы) и «Отложенные» (выводы, отложенные оператором). Карточка: логотип, имя, «1XBET • ID», номер заявки, дата, сумма и статус (синий — ожидание, красный — проблема). Тап по карточке — карточка заявки снизу со всеми действиями и кнопкой «Изменить» (редактирование в модальном окне; отдельной страницы заявки нет, тянуть карточку вверх — на весь экран).
* Проблемные заявки помечены красным блоком «Надо пополнить…» / «Касса не вернула сумму…» прямо в карточке.
* Меню → «Управление PayGo» — сводка дня, состояние касс и лента уведомлений («Ждут оператора», «Пополнений в работе», «Выводов в работе»).
* Ошибка зачисления (`failed`) — открыть заявку → «Зачислить через API» (повтор) или «Отметить зачисленным» (если зачислили вручную в кассе).
* Вывод «требует внимания» (касса не вернула сумму) — «Перепроверить код»; если сумма известна — задать через ✎ и выполнить.
* Платёж пришёл, но заявка не найдена (`payment_events: unmatched`) — Пополнения → сравнить сумму, при необходимости «Платёж вручную» с точной суммой.

## Кассы
* Меню → Кассы: включить/выключить, лимиты, пороги автоотключения (мало / критический / автовключение), проверка соединения, IP-адрес сервера для белого списка провайдера.
* Worker проверяет балансы раз в `cash_monitor_interval_seconds`; при балансе ≤ критического порога пополнения выключаются автоматически, при восстановлении выше `auto_enable_threshold` — включаются. Пороги задаются в админке, не в коде.

## Автовыплаты (Optima24)
* Включение и лимиты — в админке (Автовыплаты); канал и секреты — в `.env` (`PAYOUT_PROVIDER`, `OPTIMA24_*`). Пока `autopay_dry_run` включён, движок только пишет в лог, что отправил бы — деньги не двигаются. Снимите тест-режим лишь после одного настоящего пробного перевода.
* Схема работы: оператор пополняет Optima24 с Optima Business вручную; PayGo сам переводит клиенту готовые выводы, пока хватает баланса. Ниже `autopay_low_balance` — критическое уведомление «Пополните Optima24»; ниже `autopay_min_reserve` — автовыплаты встают до пополнения.
* Лимиты: `autopay_max_amount` (одна выплата; выше — оператор платит руками), `autopay_daily_cap` (за день), `autopay_max_age_minutes` (старую заявку отдаём оператору), `autopay_min_interval_seconds` (пауза между переводами, по умолчанию 18 с — банк просил 15–20). Движок отправляет не больше одного перевода за интервал; если выводов много, они уходят по очереди, а не пачкой.
* Ручной запуск — кнопка «Отправить через Optima24» в карточке вывода. Статус движка — `GET /paygo/api/autopay` (канал, баланс, лимиты, сколько отправлено за день, сколько заявок в очереди).
* Перевод, оборвавшийся без ответа банка, помечается «проверьте вручную в Optima24» и **не** отправляется повторно — сверьте в приложении Optima24 перед повторной отправкой.
* API Optima24 приватный: вход и перевод снимаются из приложения (или у техподдержки Optima) и вписываются в `backend/paygo/payouts/optima24.py` (метка `CAPTURE_REQUIRED`). До этого доступно только чтение баланса.
* **Несколько аккаунтов Optima24.** Задайте `OPTIMA24_ACCOUNTS` в `.env` (JSON-список: имя, логин, пароль, при необходимости счёт-источник и токен устройства). Движок сам выбирает аккаунт с достаточным балансом (берёт самый полный, чтобы не осушать один), баланс в статусе — сумма по всем. Пауза 15–20 с — общая на все аккаунты (у них один бэкенд telebank3). Один почтовый ящик кодов на все аккаунты — выплаты идут по одной, код всегда относится к текущей.
* **Код подтверждения — с почты.** Optima присылает на каждый перевод код на e‑mail. Заведите отдельный ящик только для кодов Optima (не тот, что читает платежи), направьте туда письма Optima, заполните `OPTIMA_OTP_IMAP_*` в `.env`. PayGo сам читает код и подтверждает перевод — телефон не нужен. Проверка ящика: `venv/bin/python -m paygo.cli optima-otp-test` (печатает последний найденный код). Так как выплаты идут по одной с паузой 15–20 с, код всегда однозначно соответствует текущему переводу. Если код не пришёл за `OPTIMA_OTP_WAIT_SECONDS`, заявка помечается «проверьте вручную», перевод не повторяется.

## Полуавтомат Optima24 (кнопка «Оплатить в Optima24»)
* В карточке вывода, если QR клиента распознан, есть кнопка **«Оплатить в Optima24»**. На телефоне с приложением Optima24 она открывает экран подтверждения перевода с уже вписанными реквизитами клиента и суммой — оператор только подтверждает (Face ID/PIN). Без ввода реквизитов и сканирования. Работает без API и без перехвата.
* Сама ссылка деньги не отправляет — банк всегда требует подтверждение в приложении. Это полуавтомат: один тап + подтверждение на выплату.
* Адрес ссылки настраивается: `optima_pay_link_base` (по умолчанию `https://mobile.optima24.kg/my-qr/confirm-screen?url=#`).

## Уведомления
* Меню → Настройки → Push-уведомления → «Включить на этом устройстве» (на Android — Chrome; на iPhone — добавить панель на экран «Домой»). Критические события идут отдельным сигналом.
* `ADMIN_TELEGRAM_CHAT_IDS` в `.env` — дублирование критических событий в Telegram через бота поддержки.
* После рестарта старые уведомления не отправляются повторно (`NOTIFICATION_MAX_AGE_SECONDS`).

## Типовые проблемы
| Симптом | Что проверить |
|---|---|
| Бот не отвечает / отвечает через раз | `systemctl status paygo-bot`, токен в `.env`, лог `bot.log`. `409 Conflict` в логе = запущено два экземпляра бота: `/home/PayGo/scripts/kill_stray.sh` останавливает юниты, убивает все лишние процессы именно PayGo (ручные запуски из `venv`, старый docker compose) и запускает юниты заново; другие проекты на сервере не трогает. `--dry-run` только показывает, `--sessions` дополнительно завершает все сеансы админки |
| Платёж не зачисляется | Меню → MacroDroid: есть ли событие в «Последних платежах»? Нет — проверьте макрос (адрес, ключ, тело); есть, но «Не найден» — сумма не совпала до тыйына или заявка истекла > `payment_event_max_age_minutes`. Поправьте сумму в заявке (✎ «Сумма к оплате») и нажмите «Зачислить через API» |
| Клиент оплатил не ту сумму | Открыть заявку → «Зачислить на счёт игрока» → в окне указать фактически оплаченную сумму с тыйынами (подставляется платёж из банка, если он найден) → «Зачислить». В кассу уходит ровно эта сумма, она же записывается в заявку |
| Клиент прислал чек | В заявке появляется блок «Чек клиента», уведомление «🧾 Чек к пополнению» в панели |
| Нужно поменять текст/фото шага бота | Меню → Настройки → Тексты (общие тексты) или Кассы → Изменить → «Шаги бота» (фото и текст для конкретной кассы) |
| Сменить адрес/город вывода | Настройки → Выводы (общие) или в карточке кассы (для одной кассы) |
| Касса «Ошибка» | Кассы → Проверить: сообщение провайдера (403 — IP не в белом списке, 599 — нет сети) |
| Автовыплаты не идут | Проверьте `.env` (`PAYOUT_PROVIDER`, `OPTIMA24_*`) и админку (`autopay_enabled` включён, `autopay_dry_run` выключен). `GET /paygo/api/autopay` показывает `configured`, `active`, баланс. «Пополните Optima24» = баланс ниже порога, пополните счёт с Optima Business. Заявка «проверьте вручную» = банк не подтвердил перевод, сверьте в Optima24 |
| Optima24: «вход/перевод не настроен» | Приватный API снят не полностью: впишите захваченные запросы в `backend/paygo/payouts/optima24.py` (метка `CAPTURE_REQUIRED`) |
| 401 в админке | сессия отозвана/истекла; вход заново |
