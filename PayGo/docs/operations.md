# Эксплуатация

## Ежедневно
* Админка (`/paygo/`) — экран телефона с нижней навигацией **Главная / История / Чат / Поиск / Меню**.
* Главная → «Актуальные» (пополнения в ожидании / с ошибкой и активные выводы) и «Отложенные» (выводы, отложенные оператором). Карточка: логотип, имя, «1XBET • ID», номер заявки, дата, сумма и статус (синий — ожидание, красный — проблема). Тап по карточке — быстрый просмотр с действиями, «глаз» — полная страница заявки.
* Проблемные заявки помечены красным блоком «Надо пополнить…» / «Касса не вернула сумму…» прямо в карточке.
* Меню → «Управление PayGo» — сводка дня, состояние касс и лента уведомлений («Ждут оператора», «Пополнений в работе», «Выводов в работе»).
* Ошибка зачисления (`failed`) — открыть заявку → «Зачислить через API» (повтор) или «Отметить зачисленным» (если зачислили вручную в кассе).
* Вывод «требует внимания» (касса не вернула сумму) — «Перепроверить код»; если сумма известна — задать через ✎ и выполнить.
* Платёж пришёл, но заявка не найдена (`payment_events: unmatched`) — Пополнения → сравнить сумму, при необходимости «Платёж вручную» с точной суммой.

## Кассы
* Меню → Кассы: включить/выключить, лимиты, пороги автоотключения (мало / критический / автовключение), проверка соединения, IP-адрес сервера для белого списка провайдера.
* Worker проверяет балансы раз в `cash_monitor_interval_seconds`; при балансе ≤ критического порога пополнения выключаются автоматически, при восстановлении выше `auto_enable_threshold` — включаются. Пороги задаются в админке, не в коде.

## Уведомления
* Меню → Настройки → Push-уведомления → «Включить на этом устройстве» (на Android — Chrome; на iPhone — добавить панель на экран «Домой»). Критические события идут отдельным сигналом.
* `ADMIN_TELEGRAM_CHAT_IDS` в `.env` — дублирование критических событий в Telegram через бота поддержки.
* После рестарта старые уведомления не отправляются повторно (`NOTIFICATION_MAX_AGE_SECONDS`).

## Логи
* `/home/PayGo/logs/{backend,worker,bot,support}.log`, `journalctl -u paygo-*`.
* Меню → Логи: события системы (провайдер, платежи, кассы) и действия администраторов.

## Типовые проблемы
| Симптом | Что проверить |
|---|---|
| Бот не отвечает | `systemctl status paygo-bot`, токен в `.env`, лог `bot.log` (409 Conflict = запущено два экземпляра) |
| Платёж не зачисляется | Меню → MacroDroid: есть ли событие в «Последних платежах»? Нет — проверьте макрос (адрес, ключ, тело); есть, но «Не найден» — сумма не совпала до тыйына или заявка истекла > `payment_event_max_age_minutes`. Поправьте сумму в заявке (✎ «Сумма к оплате») и нажмите «Зачислить через API» |
| Клиент оплатил не ту сумму | Открыть заявку → ✎ «Сумма к оплате» = фактически оплаченная → «Зачислить через API» (QR у клиента пересобирается автоматически, если заявка ещё активна) |
| Клиент прислал чек | В заявке появляется блок «Чек клиента», уведомление «🧾 Чек к пополнению» в панели |
| Нужно поменять текст/фото шага бота | Меню → Настройки → Тексты (общие тексты) или Кассы → Изменить → «Шаги бота» (фото и текст для конкретной кассы) |
| Сменить адрес/город вывода | Настройки → Выводы (общие) или в карточке кассы (для одной кассы) |
| Касса «Ошибка» | Кассы → Проверить: сообщение провайдера (403 — IP не в белом списке, 599 — нет сети) |
| 401 в админке | сессия отозвана/истекла; вход заново |
