# Бот поддержки

## Claude на первой линии

При заданном `ANTHROPIC_API_KEY` (`.env`, модель `ASSISTANT_MODEL`, по умолчанию `claude-opus-5`) на сообщение клиента первым отвечает Claude (`services/assistant.py`): он получает факты о сервисе (кассы, лимиты, инструкция, сроки) и историю диалога, а через инструменты — реальные данные: `get_client_requests` (заявки клиента со статусами и найденными платежами банка), `credit_found_payment` (зачисляет заявку, по которой платёж пришёл после истечения или после ошибки), `retry_deposit_credit` (повтор зачисления после ошибки кассы), `escalate_to_operator` (передача оператору с темой и приоритетом). Ответы короткие, на языке клиента; денежные действия идут через те же функции, что и в панели (`credit_deposit`), с логами и уведомлениями. Без ключа, при ошибке API или отказе модели работает цепочка правил ниже. Выключатель — Расширенные настройки → Поддержка.


Каждое сообщение проходит цепочку: **антифлуд → дедупликация → классификация → ответ из данных системы → (при необходимости) передача оператору с контекстом**.

## Классификация

Категории: `deposit`, `withdrawal`, `payment`, `verification`, `account`, `qr`, `currency`, `technical`, `faq`, `operator`. Правила — регулярные выражения на русском и кыргызском (`services/support.py: _RULES`). Кнопки быстрого доступа: статус пополнения, статус вывода, FAQ, позвать оператора.

## Автоматические ответы

* **Статус пополнения** — по последней заявке пользователя: ожидает оплаты (сколько минут осталось), платёж получен, зачислено, ошибка (оператор уведомлён), истекло, отменено.
* **«Когда будет вывод?»** — реальный статус заявки: создана/в обработке (текст о сроках из настроек `withdraw_sla_text`, без обещания конкретного времени), выполнен (время), отклонён (причина), требует проверки. Если заявка ждёт дольше 24 ч — автоматическая эскалация.
* **Комиссии, лимиты (из настроек касс), реферальная программа, кассы, режим работы, инструкция по выводу (`instruction_text` с городом/адресом из настроек), QR, ID, валюта, e-mail, блокировка, технические проблемы** — короткие конкретные ответы.
* **Чек/фото без текста** — прикрепляется к текущей заявке и передаётся оператору.

## Передача оператору

Создаётся/обновляется `support_conversations` со статусом `waiting_operator`, приоритетом и `context`: Telegram ID, username, последнее пополнение и вывод (номер, статус, сумма, валюта, касса, ID, время создания, ошибка, история событий), счётчики, наличие QR. Админы получают уведомление (push/UI/Telegram). Пока диалог у оператора (`operator`), автоматика молчит — сообщения клиента идут напрямую в чат админки. После закрытия клиенту предлагается оценка 1–5 (кнопки ⭐ в том боте, через который шёл диалог). У клиента один диалог: закрытое обращение при следующем сообщении открывается заново с полной историей.

## Антифлуд

Настраивается в админке (Настройки → Поддержка): лимит сообщений в окне, cooldown при превышении (одно предупреждение, дальше тишина), объединение серии сообщений, отправленных подряд (без задержки ответа), подавление повторов одного текста в окне (второй раз — короткий ответ, дальше молча), cooldown повторных эскалаций. Обычный пользователь ограничений не замечает.
