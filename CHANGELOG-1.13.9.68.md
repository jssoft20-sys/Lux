# PayGo 1.13.9.68

**Касса `cashier-report` требует `login`; убран агентский вызов.**

## Что показал живой `mobcash-probe` (на 1.13.9.67)

- `cashbox.getBalance` (гейтвей `/api/`) → `HTTP 200`, но JSON-RPC
  `error: unauthorized`. Этот метод **агентский** — токен кассира к нему
  не допускается. Тупик для интеграции.
- `cashier-report` (`/api/v2/cashbox/cashier-report`) → `HTTP 400`
  `login (field required)`. Важно: токен кассира **принят** (ошибка не
  про авторизацию, а про тело запроса). Значит это и есть наш endpoint —
  не хватало поля `login`.

## Что меняется

- `balance()` читает отчёт кассира с полем `login` в теле (логин кассира),
  только чтение. Агентский `cashbox.getBalance` из рабочего пути убран
  (он всё равно «unauthorized»).
- `mobcash-probe` теперь шлёт `cashier-report` с `login` (3 варианта тела)
  и печатает **сырой ответ** — чтобы увидеть, в каких полях приходят
  Баланс/Лимит.

## Честно про статус

Это шаг к числам на главном: поле `login`, которого требовал сервер,
добавлено. Остаётся подтвердить, что `cashier-report` действительно
возвращает Баланс/Лимит (а не только список операций). Для этого — один
запуск `mobcash-probe` на сервере: в блоке `=== cashier-report ===`
будет сырой ответ. Если числа там есть — они появятся на главном; если
под другими именами полей — поправлю точечно; если их там нет —
у интеграционного API кассы баланса нет, и скажу это прямо.

## Код

Меняются только `providers/mobcash.py` и `cli.py`. Фронтенд не трогается.
Установщик тот же терпимый (откат только из-за основных сервисов).

## Установка

Один блок в терминал (root, `/home`): `installer/paygo-1.13.9.68-paste.txt`.
После установки:
```
sudo -u paygo /home/PayGo/venv/bin/paygo-admin mobcash-probe
```
и пришлите блок `=== cashier-report [...] ===`.
