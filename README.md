# Continental BOT — новостной торговый бот для Binance Spot

Бот в реальном времени читает крипто-новости (24 источника), оценивает их тональность
(мгновенный лексический анализ + Claude и GPT параллельно, если заданы ключи), совмещает с
рыночными данными Binance (стакан, поток сделок, импульс цены — WebSocket, миллисекундная
задержка) и торгует спотовыми парами из белого списка вашего API-ключа. Мобильный дашборд на
порту **7066** в стиле биржи: баланс, P&L, позиции, сделки, сигналы, лента, системная шторка.

Служебное имя сервиса и папки осталось `lux-bot` / `/opt/lux-bot` — так обновление на уже
установленных серверах проходит без миграций.

> **Важно и честно.** Ни один бот не гарантирует прибыль. «5 $ за полчаса с 30–50 $» — это
> 10–15 % за 30 минут; ни одна стратегия не даёт такого стабильно, а комиссия Binance
> (0,1 % на сделку, 0,2 % за круг) съедает мелкие движения. Бот может терять деньги.
> Встроены ограничители риска (стоп-лосс, дневной лимит убытка, лимит позиций), но риск
> потери всей суммы остаётся. Сначала запустите в режиме `paper` и посмотрите статистику.

## Как это работает

```
 Binance WebSocket (bookTicker / aggTrade / miniTicker)  ──►  MarketState (мс)  ─┐
                                                                                  ├─► Сигнал по паре ─► Риск-менеджер ─► Ордер (paper | live)
 24 новостных источника (RSS, Binance, Google News, F&G) ─► Лексика (мкс) ──┐     │
                                                             └► Claude (сек) ┴─► SentimentBook (затухание) ┘
```

* **Сигнал** = `0.55·новости + 0.25·импульс + 0.10·стакан + 0.10·поток` (веса настраиваются).
  Вход — когда сигнал ≥ `BUY_THRESHOLD` (0.35). Только лонг (спот).
* **Выход** — тейк-профит (+1.2 %), стоп-лосс (−0.8 %), трейлинг-стоп (0.5 % от максимума после
  +0.5 %), выход по времени (45 мин), резко негативные новости или разворот сигнала.
* **Риск** — размер сделки `POSITION_SIZE_USDT` (но не больше 35 % свободного баланса и не
  меньше минимума Binance ≈ 5 USDT), не больше `MAX_POSITIONS` позиций, пауза по паре после
  сделки, стоп торговли при дневном убытке `DAILY_LOSS_LIMIT_USDT`, пропуск пар с широким
  спредом, устаревшими данными или экстремальной волатильностью.
* **Цикл решений** — каждые 100 мс (`DECISION_INTERVAL_MS`). Рыночные данные приходят по
  WebSocket за миллисекунды. Новости физически выходят реже: источники опрашиваются каждые
  10–45 с, бот реагирует на новый заголовок в пределах миллисекунд после его получения.
* **ИИ-анализ** — два провайдера работают одновременно: Claude (`ANTHROPIC_API_KEY`,
  модель `LLM_MODEL`) и GPT (`OPENAI_API_KEY`, модель `OPENAI_MODEL`). Каждый заголовок уходит
  обоим, оценки объединяются (взвешенно по уверенности): тональность −1…+1, монеты, влияние,
  короткое объяснение. Провайдер, который отвечает 401/403/404 или «нет кредитов», отключается
  сам, второй продолжает. Без ключей работает только лексический анализ.
* **Скальп-режим и калькулятор комиссий** (`SCALP_MODE=true`) — цели считаются от комиссии
  Binance: круг покупка+продажа = 0.2 %, тейк-профит = 0.2 % × `FEE_MULTIPLE` (2.5 → +0.5 %) плюс
  текущий спред, стоп −80 % от цели (−0.4 %), трейлинг после 60 % цели, лимит удержания
  `SCALP_MAX_HOLD_MINUTES` (12). Вход только если недавняя волатильность пары покрывает цель и
  спред не шире четверти цели — иначе сделка физически не успеет отбить комиссию.

Источники новостей: CoinDesk, CoinTelegraph, The Block, Decrypt, Bitcoin Magazine, CryptoSlate,
NewsBTC, Bitcoinist, U.Today, CryptoPotato, BeInCrypto, AMBCrypto, CryptoNews, анонсы Binance
(все / листинги / делистинги), Google News (общий + по монетам), индекс страха и жадности,
Reddit r/CryptoCurrency, а также CryptoPanic и NewsAPI при наличии ключей (`.env`).

## Запуск на сервере (порт 7066)

Нужен сервер с Linux (Ubuntu/Debian) **в стране, где Binance доступен** (из США и ряда других
стран API Binance отвечает ошибкой 451).

### Вариант 1 — архив + systemd (рекомендуется)

```bash
# на своём компьютере
scp lux-bot-1.0.0.tar.gz root@СЕРВЕР_IP:/root/

# на сервере
ssh root@СЕРВЕР_IP
tar xzf lux-bot-1.0.0.tar.gz && cd lux-bot
cp .env.example .env
nano .env            # впишите BINANCE_API_KEY, BINANCE_API_SECRET, DASHBOARD_PASSWORD, (ANTHROPIC_API_KEY)
bash deploy/install.sh
```

Скрипт ставит Python-окружение в `/opt/lux-bot`, создаёт сервис `lux-bot`, открывает порт 7066
в ufw (если он есть) и печатает адрес дашборда: `http://СЕРВЕР_IP:7066/` (логин `lux`, пароль
из `.env`).

Полезные команды:

```bash
journalctl -u lux-bot -f          # живой лог
systemctl restart lux-bot         # перезапуск после правки /opt/lux-bot/.env
systemctl stop lux-bot            # остановить
```

### Вариант 2 — Docker

```bash
cp .env.example .env && nano .env
docker compose up -d --build
docker compose logs -f
```

### Вариант 3 — вручную

```bash
cp .env.example .env && nano .env
./run.sh                          # создаст .venv, поставит зависимости, запустит бот
```

Архив для переноса собирается командой `bash scripts/make_archive.sh`; вариант с вашим `.env`
внутри (ключи уже заполнены, `nano .env` не нужен): `INCLUDE_ENV=1 bash scripts/make_archive.sh`.
Если в архиве есть `.env`, `deploy/install.sh` подхватит его автоматически.

В paper-режиме с заполненными ключами бот ничего не покупает, но раз в 2 минуты читает реальный
баланс и показывает его в плитке «Свободно» — так видно, что ключ работает с сервера.

## Обновление и смена настроек без переустановки

```bash
# обновить код с GitHub (.env и данные сохраняются), перезапуск автоматический
bash /opt/lux-bot/deploy/update.sh

# поменять любые настройки и перезапустить бот
bash /opt/lux-bot/deploy/setenv.sh TRADING_MODE=live ANTHROPIC_API_KEY=sk-ant-...
bash /opt/lux-bot/deploy/setenv.sh TRADING_MODE=paper          # вернуться к виртуальной торговле
bash /opt/lux-bot/deploy/setenv.sh --no-restart POSITION_SIZE_USDT=8
```

## Проверка ключа Binance перед live

```bash
cd /opt/lux-bot && .venv/bin/python -m scripts.check_binance
```

Скрипт читает баланс и ограничения ключа и отправляет **тестовые** ордера по каждой паре
(ничего не покупает), показывая, какие пары разрешены белым списком. Те же проверки бот делает
сам при старте в live-режиме и исключает недоступные пары.

## Переход с paper на live

1. Убедитесь, что в paper-режиме статистика вас устраивает.
2. Пополните спотовый кошелёк USDT (для одной сделки нужно ≥ 5,25 USDT; при `POSITION_SIZE_USDT=10`
   и `MAX_POSITIONS=3` комфортно 30–50 USDT).
3. В `.env`: `TRADING_MODE=live`, затем `systemctl restart lux-bot`.
4. В дашборде значок сменится на красный **LIVE**. Кнопки «Пауза» и «Закрыть все позиции»
   работают мгновенно.

## Настройки `.env`

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `TRADING_MODE` | `paper` | `paper` — виртуальные сделки по реальным ценам, `live` — реальные ордера |
| `SYMBOLS` | 21 пара USDT | Пары для торговли; должны быть в белом списке ключа |
| `POSITION_SIZE_USDT` | 10 | Сумма одной сделки |
| `MAX_POSITIONS` | 3 | Одновременно открытых позиций |
| `TAKE_PROFIT_PCT` / `STOP_LOSS_PCT` | 1.2 / 0.8 | Тейк-профит и стоп-лосс, % |
| `TRAILING_STOP_PCT` / `TRAILING_ACTIVATION_PCT` | 0.5 / 0.5 | Трейлинг-стоп |
| `MAX_HOLD_MINUTES` | 45 | Максимальное время в позиции |
| `BUY_THRESHOLD` / `EXIT_THRESHOLD` | 0.35 / −0.25 | Пороги входа/выхода по композитному сигналу |
| `MIN_NEWS_SCORE` | 0.05 | Входить только при хотя бы слабо позитивном новостном фоне по паре |
| `DAILY_LOSS_LIMIT_USDT` | 8 | Дневной лимит убытка, после него торговля останавливается до полуночи UTC |
| `MAX_SPREAD_BPS` | 15 | Не входить при спреде шире 0,15 % |
| `DECISION_INTERVAL_MS` | 100 | Период цикла решений |
| `NEWS_HALF_LIFE_MINUTES` | 20 | Период полураспада новостного сигнала |
| `W_NEWS` / `W_MOMENTUM` / `W_ORDERBOOK` / `W_FLOW` | 0.55 / 0.25 / 0.10 / 0.10 | Веса компонентов сигнала |
| `ANTHROPIC_API_KEY`, `LLM_MODEL` | — / `claude-opus-5` | Claude-анализ новостей (платно; дешевле: `claude-sonnet-5`, `claude-haiku-4-5`) |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | — / `gpt-4.1-mini` | GPT-анализ новостей (платно, нужен баланс на platform.openai.com) |
| `SCALP_MODE`, `FEE_MULTIPLE`, `SCALP_MAX_HOLD_MINUTES` | true / 2.5 / 12 | Цели от комиссии Binance и быстрый выход |
| `LLM_MAX_AGE_MINUTES` | 90 | Заголовки старше не отправляются в ИИ |
| `CRYPTOPANIC_TOKEN`, `NEWSAPI_KEY`, `EXTRA_RSS` | — | Дополнительные источники |
| `DASHBOARD_PASSWORD` | — | Пароль дашборда (логин `lux`). На публичном сервере обязателен |
| `PORT` / `HOST` | 7066 / 0.0.0.0 | Адрес дашборда |

## Безопасность ключей

* **Ключ и секрет, отправленные в чат или мессенджер, считаются скомпрометированными.**
  Создайте на Binance новый API-ключ и впишите его в `.env` на сервере; старый удалите.
* В настройках ключа: **выключите вывод средств** (боту он не нужен), включите
  «Разрешить доступ только доверенным IP» и укажите IP сервера, оставьте белый список пар.
* `.env` хранится только на сервере (права 600), в git не попадает.
* Обязательно задайте `DASHBOARD_PASSWORD` — иначе управлять ботом сможет любой, кто найдёт порт.

## Дашборд

* **Плитки**: эквити, P&L сегодня и за всё время, нереализованный результат, свободные средства,
  число сделок и винрейт. Зелёное — плюс, красное — минус.
* **Кривая эквити** с выбором периода, подсказкой при наведении и табличным видом.
* **Открытые позиции** (вход, текущая цена, P&L, стоп/тейк, кнопка закрыть) и **сделки**.
* **Сигналы по парам**: цена, изменение за 1 и 5 минут, новостной, импульсный, стаканный и
  потоковый компоненты, спред, композитный сигнал и причина, почему сделка не открыта.
* **Новости и оценка**: заголовок, источник, монеты, оценка (лексика / ИИ) и объяснение ИИ.
* **Источники** и **журнал** событий. Кнопки: пауза/продолжить, снять дневной стоп, закрыть всё.

API: `GET /api/status`, `/api/signals`, `/api/positions`, `/api/trades`, `/api/news`,
`/api/sources`, `/api/equity?hours=24`, `/api/events`; `POST /api/control/{pause|resume|close_all|reset_halt}`,
`POST /api/control/close/{SYMBOL}`; WebSocket `/ws` (снимок состояния раз в секунду + события).

## Разработка

```bash
pip install -r requirements.txt pytest pytest-asyncio
python -m pytest -q            # тесты (лексика, сущности, размер позиции, риск, paper-цикл)
python -m bot.main             # запуск (читает .env)
```

Структура: `bot/exchange` (Binance REST/WS, paper/live брокер), `bot/news` (источники,
сущности, лексика, книга настроений, Claude), `bot/strategy` (сигналы, риск, портфель, движок),
`bot/api` (FastAPI + дашборд), `bot/storage` (SQLite), `deploy/` (Dockerfile, systemd, установка).
