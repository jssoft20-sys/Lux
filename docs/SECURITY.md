# Безопасность и антифрод Somex

## Главное правило

**ФИО KYC = ФИО владельца банковского счёта.** Владелец способа оплаты не вводится пользователем — он копируется из верифицированного документа. Продавец в каждой сделке видит: «Ожидайте N KGS · Отправитель: Фамилия Имя Отчество · Банк: X. Принимайте перевод ТОЛЬКО от этого человека». Несовпадение → красная кнопка «НЕ отпускать USDT → открыть спор». Правило «банк → тот же банк» (Optima→Optima, MBank→MBank) исключает переводы через кассы/терминалы и упрощает споры.

## Аутентификация

| Мера | Реализация |
|---|---|
| Только номера Кыргызстана | `normalizeKgPhone` (`^\+996[2579]\d{8}$`), маска `555 123 456`, флаг 🇰🇬 |
| OTP через WhatsApp | Wappi `POST /api/sync/message/send`, 6 цифр, TTL 5 мин, 5 попыток, единоразовое использование, хранится HMAC-хэш |
| Анти-перебор | Лимиты в Redis: на номер/час, на IP/час, cooldown повторной отправки; глобальный throttler (Redis storage) на все эндпоинты; идентичный ответ для чёрного списка (без enumeration) |
| Сессии | Access JWT 15 мин, refresh 30 дней с **ротацией и детекцией повторного использования** (компрометация семьи → отзыв всех), макс. N сессий, сессии/устройства управляются пользователем и админом |
| Устройства | Fingerprint → таблица `Device`; **новое устройство = cooldown 24ч** на вывод и отпуск (требует доп. OTP), уведомление в WhatsApp, risk-событие |
| PIN / Face ID | argon2id, step-up токен 5 минут для отпуска эскроу и вывода |
| Админы | argon2id пароль, **обязательный TOTP** (enrolment при первом входе), блокировка после 5 ошибок, IP allowlist (глобальный + персональный, CIDR), короткие сессии, роли |

## Деньги

* **Леджер двойной записи** с блокировкой строк, инвариант Σ = 0, сверка в админке.
* **Эскроу**: USDT продавца блокируются при создании сделки; реквизиты раскрываются только после блокировки; отпуск — только продавец (чек-лист «проверьте приложение банка, не чек», сверка ФИО, hold-to-confirm, PIN, OTP при риске) или арбитраж.
* **Депозиты**: подтверждения сети → screening адреса-источника (чёрный список, история отклонений, mule-паттерн «один адрес → много аккаунтов», внешний AML-адаптер) → HIGH/MEDIUM = удержание до решения комплаенса.
* **Выводы**: quote с лимитами по уровню KYC → PIN → OTP → Risk Engine → автоодобрение до порога / ручное одобрение / risk-review → воркер трансляции → лимиты hot wallet (разовый/суточный) → **экстренная заморозка** (глобальная и hot wallet).
* **Idempotency-Key** на создание вывода.

## Risk Engine

Каждой чувствительной операции (вход, устройство, сделка, отпуск, вывод, депозит, KYC, способ оплаты) присваивается скрытый score 0–100 по правилам с настраиваемыми весами (админка → Risk Engine): новый аккаунт, новое устройство, смена устройства/телефона, VPN/Proxy, зарубежный IP, общие IP/устройства, velocity, аномальная сумма, первый депозит + крупная сделка, депозит→вывод менее часа, новый адрес вывода, чёрный список, связь с заблокированным аккаунтом, AML-риск адреса, несовпадение ФИО, доля споров, рискованный контрагент. `≥ review` → REVIEW (операция проходит с флагом/ручным одобрением), `≥ block` → BLOCK (операция остановлена, событие в очередь ревью, e-mail алерт). Ничего не банит автоматически — решение принимает человек.

Связанные аккаунты вычисляются по устройству, IP (30 дней), документу и банковскому счёту; кластеры видны в админке (Устройства).

## Файлы

Размер → magic-bytes (JPEG/PNG/WEBP/HEIC/PDF; расширение и MIME клиента игнорируются) → **ClamAV** (INSTREAM по TCP, `fail_open`/`fail_closed`) → изображения перекодируются `sharp` (уничтожает полиглоты, удаляет EXIF/GPS, ограничивает размер) → приватное хранилище (локально или S3) → выдача с `nosniff`, PDF как attachment → доступ только владельцу, участникам сделки и админу. Чек **никогда** не считается доказательством оплаты.

## Данные

* Секреты настроек, номера счетов, TOTP-сиды, ключ hot wallet — AES-256-GCM (`MASTER_KEY`).
* Поиск по номеру документа/счёту/чёрному списку — HMAC blind-index, оригиналы не хранятся.
* Аудит: append-only, `hash = sha256(canonical(row) + prevHash)`, проверка целостности в админке; все действия админов с обязательной причиной.
* Логи: pino с редактированием токенов/кодов/PIN/паролей.
* HTTP: helmet, CORS allowlist, CSP/HSTS в nginx, rate-limit на auth.

## Custody (production)

Данная реализация — MVP-уровень: hot wallet ключ в зашифрованной настройке, депозитные адреса из xpub (ключи депозитов вне API). Для production: HSM/KMS (AWS KMS, Fireblocks, self-hosted), hot/warm/cold разделение с multisig, автоматический свип депозитов с порогами, лимиты и алерты hot wallet, страховка, регулярная сверка on-chain ↔ леджер.

## Комплаенс в КР

KYC/AML/эскроу/custody должны проектироваться под лицензированную модель (закон КР «О виртуальных активах», требования к идентификации и хранению ПДн). Didit покрывает документ + liveness + face match (+ AML/monitoring за доп. плату); Sumsub — альтернатива. Перед выбором проверьте качество распознавания паспортов/ID КР и требования к локализации данных.
