```
┌─────────────┐   HTTPS/WSS    ┌──────────────────────────────┐        ┌────────────┐
│ Mobile PWA  │ ─────────────► │  API (NestJS)                │ ─────► │ PostgreSQL │
│ apps/mobile │                │  auth · kyc · wallet · p2p   │        └────────────┘
└─────────────┘                │  risk · files · admin · chat │ ─────► ┌────────────┐
┌─────────────┐                │  cron: watcher, timers,      │        │ Redis      │
```

## Модули API

| Модуль | Ответственность |
|---|---|
| `auth` | OTP через WhatsApp (Wappi), только номера +996, JWT access (15 мин) + refresh с ротацией и детекцией повторного использования, привязка устройств, cooldown чувствительных операций после нового устройства, PIN → step-up токен (5 мин) |
| `users` | Профиль, устройства, сессии, способы оплаты (владелец = ФИО из KYC, номер счёта шифруется, blind-index для поиска дублей и чёрного списка), уведомления, поддержка |
| `kyc` | Didit v2 сессии, вебхук (HMAC X-Signature / X-Signature-V2, окно 5 мин, идемпотентность по event_id), политика: страны, возраст, дубли документа → ручной ревью, уровни BASIC/VERIFIED/ADVANCED, sandbox для разработки |
| `wallet` | **Леджер двойной записи** (`LedgerService`), депозитные адреса из xpub (BIP32 → TRON base58check), watcher TronGrid (TRC20 Transfer → подтверждения → AML screening → зачисление/удержание), выводы (OTP → risk → автоодобрение/ручное → воркер трансляции → подтверждение), hot wallet с лимитами и заморозкой |
| `p2p` | Объявления (правило «банк → тот же банк»), сделки с эскроу, декларация оплаты, отпуск с чек-листом + PIN + OTP при риске, таймеры, споры, рейтинг, чат (socket.io) с детекцией увода за пределы платформы и неизменяемыми системными сообщениями |
| `risk` | Risk Engine: правила с весами (таблица `RiskRule`, редактируются в админке), score 0–100 → ALLOW/REVIEW/BLOCK, связанные аккаунты (устройство/IP/документ/счёт), чёрный список (HMAC-хэши) |
| `files` | Magic-bytes → ClamAV INSTREAM → sharp re-encode (EXIF/GPS stripped) → приватное хранилище, доступ только участникам сделки/владельцу/админу |
| `admin` | Отдельная аутентификация (argon2id + TOTP, IP allowlist), RBAC, все управляющие эндпоинты, настройки с шифрованием секретов, тесты подключений, dev-симуляция блокчейна |
| `audit` | Append-only журнал с хэш-цепочкой (`prevHash` → `hash`), проверка целостности из админки |
| `notifications` | In-app + WhatsApp outbox (cron с ретраями), SMTP-алерты администраторам |

## Состояния сделки

```
CREATED ──(покупатель: декларация оплаты)──► PAID ──(продавец: чек-лист + PIN [+OTP])──► RELEASED
   │                                            │
   ├─(покупатель отменил)──► CANCELLED           ├─(спор)──► DISPUTED ──(арбитраж)──► RESOLVED_RELEASE | RESOLVED_REFUND
   └─(таймер истёк)───────► EXPIRED
```

* На `CREATED` USDT продавца переводятся `USER_AVAILABLE → USER_LOCKED` (эскроу). Реквизиты продавца покупатель видит **только после** этой блокировки.
* Покупатель никогда не может «забрать» USDT кнопкой «Я оплатил» — только продавец или арбитраж освобождает эскроу.
* Все переходы пишут `OrderEvent` и системные сообщения в чат — доказательная база спора.

## Леджер

Каждая денежная операция — сбалансированный журнал (Σ Δ = 0), записанный в одной транзакции с блокировкой `SELECT … FOR UPDATE` строк `Balance`. Счета пользователей `USER_AVAILABLE` / `USER_LOCKED`, платформенные `PLATFORM_HOT_WALLET` (внешний контр-счёт сети), `PLATFORM_FEES`, `PLATFORM_ADJUSTMENTS`. `LedgerService.reconcile()` сверяет кэш балансов с проводками и доступен в админке (Кошельки).

## Блокчейн

* Депозитные адреса: `m/44'/195'/0'/0/i` из **публичного** xpub — API не хранит ключи депозитов. Свип на hot wallet выполняется custody-инструментом (вне API).
* Watcher каждые 30 с опрашивает TronGrid `GET /v1/accounts/{addr}/transactions/trc20`; подтверждения считаются как `nowBlock − txBlock` (по умолчанию 19).
* Выводы транслирует воркер через TronWeb (`transfer` USDT TRC20) с `feeLimit`, с учётом лимитов hot wallet и глобальной заморозки.
* `DEV_SIMULATE_CHAIN=true` — эмуляция без сети.

## Frontend

* Mobile: маршруты в `apps/mobile/src/App.tsx`, экраны в `src/screens`, API-клиент с авто-refresh в `src/lib/api.ts`, сокет в `src/lib/socket.ts`. На десктопе приложение показывается в рамке телефона (демо), на мобильных — во весь экран (PWA, `vite-plugin-pwa`).
* Admin: `apps/admin/src/pages/*`, единые компоненты таблиц/drawer/диалогов с обязательной причиной действия (попадает в аудит).
