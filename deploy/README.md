# Somex — тестовый стенд (один порт 7055)

Архив содержит собранный API, мобильное приложение и админку. Нужен Ubuntu/Debian сервер с доступом в интернет: установщик ставит Node 22, PostgreSQL, Redis и зависимости API (`npm ci`, версии зафиксированы в package-lock.json). Установка занимает 3–6 минут.

## Установка (1 команда)

```bash
tar xzf somex-test.tar.gz && cd somex && sudo bash install.sh
```

Скрипт ставит Node 22, PostgreSQL, Redis, создаёт базу, генерирует секреты в `.env`, применяет миграции, заполняет тестовые данные и запускает сервис `somex` (systemd) на порту **7055**.

Другой порт: `sudo PORT=8080 bash install.sh`. Если есть Docker: `cp .env.example .env`, заполните `MASTER_KEY`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` (`openssl rand -hex 32`) и `docker compose up -d`.

## Вход

**Приложение:** любой номер Кыргызстана (+996), код подтверждения всегда **000000**. WhatsApp для теста не нужен (если укажете ключи Wappi в админке — реальные коды тоже будут приходить, но 000000 продолжит работать, пока `TEST_MODE=true`).

**Админка:** `admin@somex.kg` / `ChangeMe!2026` (2FA в тест-режиме не обязателен; включается в Настройки → Безопасность). Другие роли: `compliance@`, `finance@`, `risk@`, `support@somex.kg` — тот же пароль.

Сессии в браузере хранятся в httpOnly-cookie (после перезагрузки страницы вход сохраняется, токены недоступны скриптам). Ограничение «вход с нового устройства» в тест-режиме отключено (`security.new_device_cooldown_hours = 0`); если оно всё же появилось — в админке: Пользователь → «Снять ограничение».

## Что проверить

1. Вход по номеру → код 000000 → KYC (для нового номера — sandbox-форма) → Профиль.
2. Способы оплаты: добавить счёт (владелец подставляется из KYC, изменить нельзя).
3. Пополнить: кнопка «+100 / +1000 / +5000 USDT» (блокчейн симулируется).
4. Купить USDT у продавца → сделка с таймером → «Я отправил оплату» (чек, антивирус) → чат.
5. Войти вторым телефоном/вкладкой как продавец (например +996 700 111 222, код 000000) → сделка → «Проверить и отпустить USDT» → чек-лист, сверка ФИО, удержание кнопки → завершение.
6. Спор: из статуса «оплачено» открыть спор → в админке Споры → решить.
7. Вывод: адрес TRON (любой `T…` 34 символа, например `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`), PIN, код 000000 → в админке Выводы одобрить (симуляция трансляции).
8. Уведомления: свайп влево — удалить, вверху «Прочитать все» и «Удалить прочитанные».
9. Модальные окна закрываются свайпом вниз за «ручку»; номер и PIN вводятся с системной цифровой клавиатуры.
10. Админка: заморозка пользователя, снятие ограничения нового устройства, чёрный список, Risk Engine, аудит, настройки (кнопки «Проверить подключение» для Wappi/SMTP/Didit/TronGrid/ClamAV).

Чтобы проверить два аккаунта на одном компьютере, используйте обычное и приватное окно браузера (или разные браузеры).

## Управление

```bash
journalctl -u somex -f          # логи
systemctl restart somex         # перезапуск
systemctl stop somex            # остановка
nano /path/to/somex/.env        # настройки (после правки — restart)
```

## Отключение тестового режима

В `.env`: `TEST_MODE=false`, `DEV_SIMULATE_CHAIN=false`, заполнить Wappi/Didit/TronGrid, поставить nginx с HTTPS (см. `infra/` в репозитории). Без HTTPS не работают PWA-установка и часть API браузера (камера в Safari).
